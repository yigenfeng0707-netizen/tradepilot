# 定价决策参考（运营输入，不是定价表）

> 定价是运营决策，代码侧不拍单价。本文把**已就绪的真实数据**和**计算框架**
> 集中在一处，价格由运营拿数字填。所有"成本"均指 LLM 网关侧 token 成本。

## 1. 已就绪的计量数据（真实记账，可复算）

`llm_usage` 表（`app/usage.py`）按租户×天记账，来源是 LLM 网关响应的
`usage` 字段（`llm.chat` 深处读取，记账失败不影响业务）。**不是估算**。

真实端到端样本（2026-11-01，书生 InternAI 网关，Atria-Dawn）：

| 场景 | 调用 | prompt | completion | 权重扣减 | 耗时 |
|---|---|---|---|---|---|
| 客服对话（含 LLM 回复） | 1 | 86 | 650 | 1 | 秒级 |
| 内容生成（英文 Listing，含市场事实回填） | 1 | 239 | 1,099 | 2 | 108s |

查看入口：租户自查 `/api/me/usage`（我的用量页）；运营侧
`/api/admin/trends`（看板）与 `/api/llm_usage` 聚合。

## 2. 成本计算公式（单价进价目表，不进代码）

```
单次调用成本 = prompt_tokens × 输入单价 + completion_tokens × 输出单价
单租户日成本 = Σ(当日各场景 calls × 对应成本)
```

单价查当前网关价目（会变，**不写进代码/文档正文**）：
https://discovery-api.intern-ai.org.cn 价目页，按所用模型（Atria-Dawn）
取输入/输出每百万 token 价。

## 3. 每任务成本怎么估

一次标准全链路任务的 LLM 调用结构（规则决策为下限、LLM 每步决策为上限）：

| 环节 | 是否走 LLM | 预计调用 |
|---|---|---|
| 规划（每步） | 可选（无 Key 走规则） | 0–8 次 |
| Listing 工坊 | 是（核心） | 1–2 次（不合格重试 1 次） |
| 文案审计 | 否（纯函数） | 0 |
| 客服 FAQ 生成 | 是 | 0–1 次 |

**建议**：上线前跑 3–5 次真实全链路任务，从 `llm_usage` 取**单任务
token 均值**作为成本锚点——样本比任何估算可靠，且记账已经就位。

## 4. 定价决策框架（三选一或组合）

1. **成本加成**：单任务成本 × (1 + 目标毛利率)，叠加平台固定成本摊销。
   配额权重（`TRADEPILOT_TENANT_DAILY_LLM_LIMIT`，默认 100）天然构成
   每租户日成本上限——把权重上限换算成钱就是"单租户日成本封顶"。
2. **免费+付费分层**：免费层用配额硬顶（现有机制，零开发），
   付费层提高 `TRADEPILOT_TENANT_DAILY_LLM_LIMIT`——
   **改一个环境变量就是一档套餐**，不需要新代码。
3. **按量计费**：`llm_usage` 已按租户×天记账，就是计费账单的原始凭证；
   差的只是"把 token 换成钱"的价目表与出账周期。

## 5. 明确不做的

- 不在代码里写任何单价（价格波动会让代码撒谎）；
- 不用"行业均值"替代真实记账样本；
- 免费期不标虚假价格（Pricing 页已收口为"内测免费，定价待定"）。
