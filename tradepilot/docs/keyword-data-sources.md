# 关键词数据源：能拿到什么、要花多少钱、现在该不该接

> 结论日期：2026-10-31　适用代码：`app/tools/keywords.py`
> 用途：① 说明当前关键词层为什么**不提供搜索量**；② 给出三条升级路径的真实门槛与成本；
> ③ 定下接入契约，凭据/报告到位即可插拔，不必改架构。

## 一、结论速览

| 路径 | 费用 | 前置门槛 | 能拿到 | 现在值得做吗 |
|---|---|---|---|---|
| **A. 广告搜索词报告**（Amazon Ads API / 后台导出 CSV） | **API 免费**，只花广告费本身 | 广告账户（**不需要商标**） | 买家真实搜索词、曝光、点击、转化 | **值得**：门槛最低、数据最硬 |
| **B. Brand Analytics**（SQP / Top Search Terms） | 报告**不额外收费** | **品牌注册** → 需已注册/申请中商标 | 全站搜索词排名、点击份额、转化份额 | **暂不**：商标 ¥3k–8k + 6–12 个月 |
| **C. 第三方工具**（Helium 10 / Jungle Scout / Keepa） | $29–99/月 | 无 | 搜索量**估算值** | 不推荐进参赛材料 |

一句话：**接口不要钱，卡的是资格。** 而资格里最贵的是商标，不是 API。

## 二、逐条核实

### A. 广告搜索词报告（推荐路径）

- 亚马逊广告 API 的官方 FAQ 明确：使用该 API **无需向亚马逊广告支付额外费用**，费用只来自投放本身。
- **关键差异**：广告的搜索词报告（Search Term Report）只需要**广告账户**，**不要求品牌注册**。
- 数据性质：它记录的是**真实买家的真实搜索词**，以及这些词带来的曝光/点击/转化——比任何"月搜索量估算"更硬，因为它是你自己账户的成交数据。
- 局限（必须如实说）：样本只覆盖**广告触达过的词**，不是全站词库；新词没有历史数据。

### B. Brand Analytics

- SQP（Search Query Performance）、Top Search Terms、商机探测器等报告**不额外收费**，随卖家账户提供。
- 前置条件是 **Brand Registry**，而 Brand Registry 要求**已注册或申请中的商标**：

| 项目 | 费用 | 周期 |
|---|---|---|
| 美国商标官费（USPTO） | $250–350 / 类 | — |
| 代理服务费 | ¥2,000–5,000 | 6–12 个月下证 |
| IP Accelerator（加速拿品牌注册） | 通常 ¥8,000+ | 2–8 周 |

- 对距提交只剩 10 天的参赛作品，这条路**投入产出不成立**。

### C. 第三方工具

- Helium 10 / Jungle Scout / Keepa：$29–99/月起。
- 它们的"搜索量"是**估算模型输出**，不是亚马逊原始数据。写进 BP 会被追问"你的数从哪来"，答"第三方工具的估算"不如答"我们不给这个数"。

### D. 关于"SP-API 2026 年起收费"的说法（**未核实，不要引用**）

搜索中出现中文博客称"2026 年起第三方开发者年费 $1,400 + GET 调用阶梯计费"，但同批来源**自相矛盾**（一说 4/30 起收，一说 5/12 已取消），且在亚马逊官方开发者文档与 usage plans 页面**核实不到该条款**。

> 处理方式：**不写进 BP、不写进答辩稿**。若必须提及，只能说"官方页面未列出调用费用，卖家侧成本是专业账户月租（$39.99/月）"。

## 三、当前实现处于哪一档

`app/tools/keywords.py` 走的是**第四条路：从真实竞品标题做词频观测**。

它给出的 `competition_proxy` 全部可由样本复算：

```json
{
 "sample_size": 5,
 "core_term_coverage": 0.8,   // 核心词出现在多少比例的竞品标题里
 "avg_title_len": 96.0,       // 竞品标题平均长度
 "distinct_terms": 23,        // 观测到的不同词数
 "_说明": "竞争度代理：核心词覆盖率越高说明该词越拥挤；本作品未接入搜索量数据源，故不提供搜索量与竞争度评分"
}
```

**为什么不填一个"月搜索量 12,000"**：那是全项目最容易被一戳就破的假数据。`tests/test_keywords.py` 里有专门用例守着——一旦有人"顺手加个月搜索量"，测试直接失败。

**这套指标的诚实边界**：
1. 它描述的是「**买家在搜什么 / 竞品在写什么**」，不等于「**本品有什么参数**」——所以标题只放核心词 + `[ADD]` 占位符；
2. 样本来自单一源（当当），**不代表美国站词库**，跨站点结论必须重采；
3. 它不能回答"这个词值不值得打"，只能回答"这个词挤不挤"。

## 四、接入契约（**已实现**，配一个环境变量即可启用）

代码在 `app/datasources/ads_report.py`，接入点 `keywords.build(..., ads_report=...)`：

```bash
# 启用方式：指向卖家后台导出的搜索词报告 CSV，并声明报告周期
export TRADEPILOT_ADS_REPORT=/path/to/search_term_report.csv
export TRADEPILOT_ADS_PERIOD="2026-10-01~2026-10-31"
```

映射后的结构：

```python
{归一化词: {"impressions": int, "clicks": int, "orders": int,
            "spend": float, "sales": float, "ctr": float, "cvr": float}}
```

| 字段 | 未配置 | 配置后 |
|---|---|---|
| `search_volume` | **不存在**（不输出） | **仍不输出**——广告报告没有搜索量字段，只有曝光/点击 |
| `impressions` / `clicks` / `orders` | 无 | 真实值，挂在命中词的 `entry["ads"]` 上 |
| `competition_proxy` | 覆盖率代理 | 保留，作为无广告数据时的降级口径 |
| `search_term_evidence` | `data_source: not_configured` | `data_source: ads_search_term_report` + 周期 + 命中词数 |

**降级规则**：报告未配置 → 输出 `data_source: "not_configured"`，代理指标照常给，
**不报错、不猜数**。所以 BP 可以写"数据源可插拔，缺凭据时降级为代理指标"，
而不是空口说"可扩展"。

**已处理的三个真实坑**（`tests/test_ads_report.py` 有对应用例）：
1. 报告末尾的 **Total 合计行**搜索词列写的是 `Total`、曝光却是数字，混进来会让曝光翻倍 → 单独识别并计数；
2. 表头中英文混用（`Customer Search Term` / `客户搜索词`）→ 别名收敛，**认不出就拒绝猜**；
3. 千分位与百分号（`"1,200"`、`12%`）→ 解析失败返回 None 而不是 0。

## 五、答辩口径（三问三答）

**问：你的关键词搜索量数据从哪来？**
> 我们没有搜索量。我们给的是从真实竞品标题里统计出的词频与覆盖率，每个词附证据标题，可回访原页核对。搜索量需要 Brand Analytics，那要求商标与品牌注册，成本 ¥3k–8k、周期 6–12 个月，在参赛阶段不成立——所以我们选择不给这个数，而不是编一个。

**问：那你的关键词优化有依据吗？**
> 有，但依据的层级要说清：**词的存在性**来自真实观测（可复算），**词的商业价值**我们不评价。A9 的前置核心词结构、Search Terms ≤250 字节、不与标题重复、去重——这些是平台规则，与搜索量无关，我们已经全部实现并做了审计校验。

**问：如果给你一个广告账户，多久能升级？**
> 已经升级完了——适配器在 `app/datasources/ads_report.py`，指向报告 CSV 的两个环境变量
> （`TRADEPILOT_ADS_REPORT` / `TRADEPILOT_ADS_PERIOD`）设好即生效，不改编排、不改前端。
> 剩下要做的只是用真实报告验证字段匹配（表头别名已覆盖中英文常见写法）。
